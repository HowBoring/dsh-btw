# 07 · Architecture Decision Records

Each ADR is a deliberate design decision for `dsh-btw` v1, not a claim that upstream DSH implements this feature.

## ADR-001 · Separate side-turn service, not main Agent input

**Choose:** invoke independent `ctx.llm` call from `BtwService`. **Reject:** `agent.followup`, `agent.steer`, `agent.inject` as normal BTW. **Why:** they modify main Agent state and may wake/interrupt ReAct. **Consequence:** BTW must own its own request lifecycle, cancellation and bounded retries.

## ADR-002 · Latest observable immutable Host cut

**Choose:** snapshot committed `Session` events + live stream observation at Host `ask` admission, before first asynchronous step. **Reject:** waiting until after history I/O/LLM preparation. **Why:** otherwise context drifts after user submitted BTW. **Consequence:** include event cursor and live Attempt coordinates; clarify Host-time semantics.

## ADR-003 · Use public Agent and LLM events

**Choose:** `llm/stream`, `isAgentLoopRequest`, `agent/assistant-stream`, `session/event` and `BlockAssembler`. **Reject:** patching ReactLoopAgent private state solely for BTW or reading Web rendering text. **Why:** code-proven public seams in rc.2 and current master. **Consequence:** bounded process-local mirror; late subscription has reduced coverage.

## ADR-004 · Provider-safe Side Context Normalizer

**Choose:** matched tool history prefix + side-only pending-operation descriptions and admissible partial text. **Reject:** forwarding raw unmatched Tool Calls and inventing success ToolResults. **Why:** provider protocol validity and safety. **Consequence:** fidelity/compatibility trade-off documented and tested per model route.

## ADR-005 · Never execute BTW-generated tools

**Choose:** side answer is read-only. **Reject:** running tools from side model response. **Why:** BTW is independent consultation. **Consequence:** model may see schemas for cache reuse but ToolCalls are not executed and must not be presented as succeeded.

## ADR-006 · Topic-scoped history, new main snapshot every turn

**Choose:** selected Topic's previous Q/A messages plus **new** `MainContext(t)` for each follow-up. **Reject:** including unrelated BTW topics or pinning first main context forever. **Why:** verified OMP follow semantics.

## ADR-007 · Session-scoped Storage Domain, not Session Events

**Choose:** `dsh-storage-domain` for non-model-visible Topic documents keyed by SessionId. **Reject:** main `user/message`, main `assistant/message`, or command lifecycle as BTW history. **Why:** separate lifespan, data privacy, cold history access. **Consequence:** cross-process lease parity not inherited.

## ADR-008 · Single Host writer V1

**Choose:** restrict V1 deployment to a single active Host writing BTW Domain. **Reject:** assuming JSON `rename` or in-memory `update` supplies distributed CAS. **Why:** DSH JSON backend has no cross-process lock. **Future:** authoritative lease/fencing or separate OMP-like store.

## ADR-009 · Persist-first admission

**Choose:** durable `running` Topic/Turn before model call; terminal durable before authoritative settled notification. **Reject:** starting provider request before history ownership. **Why:** restart and duplicate handling. **Consequence:** startup cancellation needs explicit state machine.

## ADR-010 · Idempotent `requestId` and one active BTW per Session

**Choose:** identical request id yields same receipt; competing new/follow requests refused. **Reject:** implied cancel/queue. **Why:** mirrors OMP UX and simplifies follow-up ordering. **Consequence:** protect active slot before first await, clean it after terminal settlement.

## ADR-011 · Detached Host worker, independent stream subscription

**Choose:** `ask` returns admission receipt; `watch` reads snapshot and streams updates; `cancel` stops side worker. **Reject:** single long-lived `ask` RPC tied to browser disconnect. **Why:** browser refresh/reopen should not cancel answer. **Consequence:** Host manages task disposal and lifetime.

## ADR-012 · Feature-owned Remote API

**Choose:** typed `@Remote` methods with Session access control, autogenerated Client binding. **Reject:** untyped ad hoc WS, manual client generator copy, or grafting feature semantics into generic `packages/api`. **Why:** DSH's documented business ownership and gateway rules.

## ADR-013 · Typed Client input route, not main composer default sink

**Choose:** dedicated BTW panel plus leading `/btw` input claim. **Reject:** sending `/btw question` as a regular user prompt; pretending a bare `commandUi.register` handles arguments. **Why:** an input must never reach main Agent. **Consequence:** exact `ui-input-trigger` contract and lifecycle validated before implementation.

## ADR-014 · Auxiliary identity and retry policy

**Choose:** distinct side request identity/purpose and bounded retries, with route validation. **Reject:** sharing main live request signal/provider conversation state, assuming `dsh-llm-retry` applies to arbitrary calls. **Why:** provider and checkpoint semantics differ. **Consequence:** side-specific retry classification and separate metrics.

## ADR-015 · No implicit side-to-main promotion

**Choose:** inject/branch interfaces reserved for later user-authorized development. **Reject:** auto-steering main Agent from BTW answer. **Why:** distinct human authority and side effects.

## ADR-016 · History read must be cold

**Choose:** list/get read storage directly by Session ID with access checks, no Agent lookup that wakes cold Session. **Reject:** mandatory live Agent for reading history. **Why:** Session-scoped history persists after the main worker disappears.

## ADR-017 · Restore orphaned `running` as `interrupted`

**Choose:** reconcile old owner generation to terminal interrupted; no automatic LLM replay. **Reject:** leaving permanent running or silently re-running a paid question. **Why:** OMP-style recovery and deterministic persistence.

## ADR-018 · Correctness first, cache second

**Choose:** protocol-valid context and isolation even if cache misses. **Reject:** corrupting provider request to mimic OMP byte-for-byte cache prefix. **Why:** DSH adapters differ; cache behavior is route-dependent. **Consequence:** instrument cache hit tokens and evaluate after functionality passes.
